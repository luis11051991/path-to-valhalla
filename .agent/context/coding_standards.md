# Coding Standards

- Mantener el estilo existente del repositorio.
- Preferir cambios incrementales sobre refactors grandes.
- Usar nombres claros y coherentes con el codigo actual.
- Evitar duplicar logica cuando ya exista una utilidad o patron local.
- No introducir dependencias nuevas sin justificar su necesidad.
- No mezclar reglas de negocio extensas dentro de componentes o handlers largos.
- Validar inputs en backend cuando se toquen endpoints.
- No hardcodear secretos ni configuracion sensible.
- Ejecutar la verificacion mas cercana al area modificada.
